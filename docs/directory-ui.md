# Awesome JEV directory UI

This document owns the directory's product-specific composition and behavior. Apply the stable visual tokens and review rules in [design.md](design.md); do not duplicate them here. The implementation lives in `src/App.tsx` and `src/components/*`.

## Reader and data

The current page helps readers find curated TypeSafe Jev / System One GitHub projects, judge their recorded summary and metadata, and inspect the original repository. It reads [`data/github.json`](../data/github.json). A distinct Jev news view reads [`data/news.json`](../data/news.json). Keep UI chrome localized in `src/i18n/locales/*` and retain source titles and summaries in their original language.

The opening viewport should reveal identity, searchable inventory, active controls, and the start of results. Keep the result set dominant rather than placing a marketing masthead ahead of the reader's task.

## Pagination

All projects, every project category, Top 100, news and each Saved source show at most 50 items per page. Search and filtering run over the complete applicable result set; sorting happens before slicing. Sidebar counts and search-result counts remain full totals. Date headings do not consume news item slots. Top 100 membership uses global star rank; Stars order uses that same tie-breaker, so the second page shows ranks 51–100.

The parent language route validates positive safe-integer `page` and the known `sort` values. Page 1 omits `page`. Each result section reuses DirectoryPagination only below its cards/list; it shows the item range, bounded page numbers, Previous and Next. Desktop has at most seven page-number/ellipsis slots; below `sm` it has at most five so 320px screens do not overflow. A single-page result has only its range. Zero results have no pager. The UI primitives adapt the shadcn base-nova Pagination source, retain our Base UI Button, semantic tokens and Phosphor icons, and use localized accessible names.

Pagination uses real links that work with modified clicks. Ordinary clicks navigate with TanStack Router, focus `#main`, and position it below the sticky header without animation. The selected project sort travels in pagination links. Search remains in component state; it is not written into URLs, chat prompts or analytics. Changing search or sort resets to page 1 with replace navigation. Changing categories or Saved source/category starts on page 1. View changes keep the current page. Out-of-range pages clamp to the last page, then replace the URL without adding history.

Project and news previews retain the background page and filters in their unmasked route. Browser Back and Close restore that background. The public masked URL remains the standalone project/news address. Language changes preserve the public query string. Page refresh reads the requested page before rendering, not only after hydration.

Canonical and language-alternate links identify the normalized page. Only directory index paths use selective Worker-first routing so query pages receive request-specific SSR; detail HTML, machine documents and static assets remain asset-first. Pagination does not split JSON stores, change stable IDs, export favorites or reduce the browser's complete local project projection.

## Page composition

- The full-width sticky header contains the site title and the source-repository link, a Submit a project link, theme menu, and language menu. The submission link opens the GitHub Issue form in a new tab, using the existing ghost button and Plus icon. Below 640px it is a 36px icon control with a localized accessible name; wider screens also show the localized text. It has no new modal, animation, client data loader or site-side form backend. The title returns to all projects and the top of the page. It remains the homepage H1; category pages render it as a plain brand container and use the category name as their single H1 in the results area. It uses the attributed React Bits `DecryptedText` source and its `motion/react` dependency with `speed=100`, `maxIterations=10`, `sequential=true`, `useOriginalCharsOnly=false`, `revealDirection=start`, `animateOn=hover`, and `clickMode=once`. The component's own character pool and reveal state remain upstream-owned. `maxIterations=10` has no effect in sequential mode; `clickMode` is inert outside click mode. Only pointer entry starts the decrypt; pointer exit restores the complete title, and a later entry replays it. There is no automatic loop. Reduced-motion readers see a static title. An invisible label reserves the final width without layout shift; the animated text stays on one line and may overhang during scrambling rather than wrap and clip the final letters. Both menus mark the current choice. Theme offers System, Light, and Dark; System follows operating-system changes, and selecting it clears any saved override. An effective color change uses a brief native crossfade where supported, but skips motion when the reader requests reduced motion. The language menu lists English and 简体中文, and both explicit theme and language choices persist across reloads. The header has no routine bottom divider.
- Language is a route property, not a post-hydration visual correction. English keeps the original URL; Chinese and Japanese use `/zh` and `/ja` plus the same path. Switching languages loads the equivalent prerendered page and stores the explicit choice; an unprefixed first visit uses that choice or, if absent, the browser's primary language before body paint. Do not infer language from IP geography. Project cards, list rows, title links, category navigation, and masked previews remain within the selected language variant. Interface copy is translated; upstream project and news titles and summaries remain source data.
- The centered content frame contains a full-width ASCII wordmark, two-line tagline, and data-update time when build history supplies one. Never manufacture a timestamp. The wordmark fits by CSS container width from first paint rather than resizing after hydration.
- On wide desktops (1280px and up), navigation occupies a 216px left rail beside the main results. The shared page frame is 1160px at most: rail and frame widths change together, preserving the 32px gap and the result-card width. Labels stay on one line with counts in their own right-aligned space. The sticky rail scrolls vertically on short viewports; its nav fits the rail width rather than retaining a one-pixel-wider max-content box that creates a horizontal scrollbar. Below that breakpoint the same navigation opens the existing shadcn/Base UI left Sheet, leaving the full content width to the cards. The Sheet is a restrained 288px navigation panel, not a page-width overlay: its 56px header repeats the site's `Awesome JEV` brand link at the same top-left position, with an aligned close action and an accessible Categories dialog title; the list scrolls independently below it. The wordmark, results, and footer share the wider frame's edges. Top 100 Starred, Jev news, and Saved stay as three fixed shortcuts above the divider. All projects begins the project category group below it; only the categories below that point follow a stable English-label alphabetical order, with Other last, shared by both language settings. Top 100 Starred shows the highest-starred projects in the whole catalog; its limit is already in the label, so no duplicate count appears on the right. The cutoff uses global star rank, not the current search or sort order. Saved sits directly below Jev news; its browser-local count alone uses a compact outlined badge, while other counts remain aligned text from their respective data stores.
  The menu rows share a compact width based on the longest localized label and its count, with a 208px floor so shorter translations do not make the selection surface collapse. Counts still form one right-aligned column; only the Saved badge sits immediately after its label.
- Main controls are an underline search field, Stars / Date / Name sort, and cards / list view. Below 640px, a two-column Grid reserves its full first row for the compact category trigger; sort stays left and view stays right on the second row, regardless of category label length or locale. From 640px upward the existing wrapping Flex layout remains unchanged; from 1280px the category trigger gives way to the sidebar. News and Saved do not render GitHub sort/view controls or an empty operation row. Search is GitHub-only; query and the selected shortcut or category filter the results, sort orders them, and view changes their presentation. The Stars button has no ambiguous inventory count. Preserve the query when no items match.
- The cards view assigns consecutive results left-to-right across two or three columns, then continues downward within each column. It keeps cards at natural height rather than stretching them. Narrow screens use one column. TanStack Virtual mounts only the cards near the viewport and preserves their space with estimated or measured heights; the complete catalog stays in source data and addressable project pages, not in the live DOM. Card boundaries remain visible on every mounted card. The list view is a ranked table-like list of rank, project, and stars, not an activity dashboard; it also virtualizes its single lane so switching views does not mount the whole catalog.
- The footer follows the current page of results and the bottom pager, with the community source note and Agents links. Keep the opening and closing of the page connected even when the filtered result set is short.

The news shortcut swaps the main result area, not the header or design system. It has local text search, source attribution, newest-first order, and a 50-item pages and a bounded TanStack Virtual timeline within each page rather than rendering an unbounded archive at once. Its first 16 cards stay in normal document flow for stable prerendered HTML; measured variable-height rows and date headings after them are mounted only near the viewport. Below the `sm` breakpoint, each news score occupies its own left-aligned metadata row below the source and time. At `sm` and above, the score stays right-aligned on the source row. The bookmark keeps its top-right slot. Unlike the compact GitHub grid, news uses full-width cards grouped by Shanghai calendar date with a time rail, source line, AIHOT score when present, title, complete API summary, complete optional original title, and complete optional selection reason. Do not truncate these scarce reading fields merely to equalize card heights. The layout borrows the reading order of AIHOT's timeline but retains our tokens and radii. A plain click opens our own accessible, dismissible summary dialog with the original-source and AIHOT reading links. Its masked TanStack route exposes the stable `/news/{id}` URL; browser Back closes the dialog and returns to the originating News or Saved view, while direct navigation or refresh opens the prerendered standalone summary card. Modified clicks reach that HTML directly. There is no redundant “View details” label on the card: the dialog and standalone card supply outbound actions, not a promised full article. Neither claims to display article body or media, because the official API does not expose those fields; see [news.md](news.md) for the source boundary.

Saved is a browser-local reading list, not a repository data source or an account. The one `SaveButton` component appears on project cards, list rows, news cards, and both previews. It uses Phosphor's single-chevron `BookmarkSimple` rather than a star, so GitHub stars retain their original meaning. The visible project title is an internal detail link with a stretched click area over the card; `SaveButton` sits separately in `CardAction`, never inside that link, so activating it must neither navigate nor open the preview. On project cards the button sits in `CardAction`, centered to the title row without contributing to its row height; its icon—not the invisible button box—aligns with the card's right content inset. `CardDescription` spans both grid columns and keeps the full card width. The rank badge replaces the redundant GitHub mark at the start of the title row. No title or header padding is added to simulate the button column. On news cards it aligns with the source row's right content edge without crowding source or score. List rows align it to the row's right content edge. Cards and rows use a visually compact 32px control with an invisible 40px pointer target; previews keep a 40px control beside Close. Visible focus, `aria-pressed`, and distinct add/remove labels make the state usable without relying on color alone.

The Saved view separates projects from news, then offers only populated categories from each source's existing taxonomy; it does not invent user folders or merge incompatible category systems. Its search acts on the selected source, and cards reuse the regular project/news components and preview behavior. The active source and each source's category live in validated `/saved` search params, so leaving this view and using browser Back restores the same subfilter. Returning from either preview preserves that state; a news preview adds one masked history entry while hiding only its transient `preview` param from the public `/saved` URL. Browser storage contains only source-namespaced IDs and save times, never copies of titles or summaries; current catalog data owns display. Missing catalog IDs appear as removable unavailable entries rather than showing stale copied content. Storage denial leaves the displayed state unchanged and shows an error; updates in another tab refresh this view. Clearing browser data or switching devices loses these bookmarks. No key, analytics, server sync, or Action write is involved.

## Category and standalone discovery

Project and news preview containers delegate their shared modal shell to `src/components/PreviewDialogFrame.tsx`; callers keep data, title/source actions and masked navigation. Project cards, ranking rows and news cards mark their complete bounds as `data-preview-origin`. The frame locates that source from the actual trigger, flies from its center to the centered popup, and remeasures the same source on return. The trigger still owns focus restoration, not origin sizing. Removed or offscreen sources only fade out. The frame also owns the backdrop, scrollable description and Motion presence lifecycle. Closing preserves the previous preview content through its exit, including news previews whose route-derived item immediately disappears. Arc timing and reduced-motion rules belong in [design.md](design.md); direct detail pages and category navigation are unchanged.

An interrupted close can reopen without an obsolete animation completion removing the active popup; selecting another card updates the return identity. A removed or hidden trigger recovers focus within the existing `#main` container rather than leaving focus on the document body; Base UI prefers that container's first tabbable child.

A category's result area begins with one short H1 and a purpose description from the same locale message keys as its search metadata. This is navigation context, not a marketing masthead or autogenerated repository prose. Results remain dominant; homepage composition, virtualization and source order are unchanged.

Standalone project details turn the recorded category label into a same-language category link. Below the main project card, at most three same-category recommendations appear only when non-generic topics overlap. Each has a title link, original summary and matching-topic explanation; no invented star/quality ranking. No-match and Other omit the block. GitHub remains the explicit, unobscured exit. Existing masked previews do not gain another recommendation loader or a changed history/focus contract.

Only production outbound/category/related clicks use optional non-blocking Umami events. Search input and Saved remain outside event tracking; development previews do not load the tracker.

## Card ordering algorithm

`CardMasonry` receives items **after** search, filter, and sort. It must not change that sequence. The viewport breakpoint selects one, two, or three lanes; items are assigned round-robin to those lanes, so the first reading row is left-to-right and each lane retains source order. TanStack Virtual handles window scrolling, a bounded overscan, and measured variable card heights with a 16px gap. A uniform initial height estimate pins lane assignment before any card is measured; assigning each new card to the currently shortest measured lane would reshuffle rank order during hydration and scrolling. Resize and font changes invalidate sizes and remeasure the mounted cards. Card identity, not array position, keys measurements across filters and sorts.

The prerendered HTML cannot know visitor viewport size or card heights. It includes only an initial bounded slice of cards. Below 40rem, CSS displays those cards in one-column document flow immediately, even with JavaScript enabled but still downloading; hydration measures their natural heights before switching to the existing virtual window. Until that switch, keep the SSR prefix mounted and preserve the reader's actual scroll position in both the browser and Virtualizer: initial synchronization must not reset it, and size measurements must not apply virtual-layout compensation to natural flow. The ready commit changes both the rendered window and positioning mode together, then restores the library's default size compensation. At wider widths, the client establishes the actual lane count and measures mounted cards before exposing them; up to 18 token-based skeletons cover the first rows until then. The skeleton is not data and is hidden from assistive technology. Without JavaScript, the initial slice remains visible and individual project routes and the generated README remain available; the full interactive directory requires JavaScript. Do not pre-render all 1,000-plus cards into the homepage merely to make the initial HTML exhaustive: that defeats the DOM and memory bound. Standalone project pages and the sitemap remain the crawlable complete inventory.

True masonry cannot also guarantee strict row-by-row visual rank order when card heights differ: a later card in a shorter column can start above an earlier card in a taller column. Source and keyboard order remain unchanged; rank labels make the intended ordering explicit. On narrow screens, cards use one lane. Virtualization unmounts distant cards; it does not hide thousands of retained nodes with `content-visibility`. Keep a rendered window large enough to avoid blank gaps during ordinary scrolling, but bounded regardless of catalog size.

## Project evidence

GitHub cards show title, summary, source repository / language, recorded stars / forks, and tags when available. Separate title, summary, source, metrics, and tags with a consistent 12px vertical rhythm; changing row spacing must not squeeze the title/action columns or the summary width. Keep stars and forks in one non-wrapping flex row; their variable-width numbers do not need fixed grid columns. Open-issue counts are neither persisted nor shown: without context, the number is not a useful quality signal. Global star rank uses the existing subdued outlined number badge before the title, replacing the redundant GitHub mark; it is not a second star count or the current filtered-list position. The top-right corner stays reserved for Save, and long titles wrap beside the badge rather than moving it to a separate line. Counts and sort keys come from `sourceMeta`; never substitute invented values. Peer cards keep the same type roles and metadata order even when summaries have unequal lengths.

Cards with a recorded GitHub star count strictly above 1,000 keep the existing Card as the interactive content inside the official React Bits `StarBorder` component. The upstream demo uses two fading horizontal sweeps; on a much larger card with a one-pixel edge, those gradients appear as intermittent flashes. The site adapter keeps the component and its two decorative layers but replaces their path with two continuously rotating, opposite conic highlights at the demo's five-second cycle. This is a card-specific adaptation, not a claim that upstream already traces all four sides. The one-pixel wrapper uses site `border` and `ring` tokens and owns the single visible border, while the inner Card keeps its content and action layout without a duplicate ring. The adapter also removes the upstream demo padding, colors, and 20px radius in favor of the site's 8px card radius. Reduced-motion visitors get the static token border. The threshold follows refreshed `sourceMeta.stars`, not rank or an invented score. Only intersecting featured cards animate while the document is visible; the other borders stay static, with their decorative CSS animations paused. Observe only featured wrappers rather than the entire catalog.

An ordinary click on a card or list row opens the single shared project preview and changes the address to its stable `/projects/:owner/:repo` URL. The stretched title anchor itself points to that internal URL, so modified clicks, JavaScript-disabled browsing, copied links, and direct requests reach a prerendered standalone detail page. The original GitHub URL is a separate explicit action. Preview and standalone page share one content component and show only stored facts: title, repo identifier, summary, category, language, available star/fork counts, optional pinned review-source link, and tags. Neither fetches a third-party README. Make the summary the main reading block; counts are compact evidence, not a three-column dashboard. Do not repeat the rank badge.

The preview has a dim backdrop and one restrained surface. Project and news dialogs share a header component: the title's own line height owns the first row and its top inset matches its left inset; the save and close controls are positioned over that row and centered to it, never increasing the row height or pushing the title down. Source metadata spans a separate full-width row and cannot shift the controls. The shared footer gives the outbound action equal top and bottom padding at the same responsive inset as the header; enlarging its bottom space must enlarge its top space, not move the button off-center. A narrow dialog scrolls its content without covering it with the header or outbound action. The GitHub action is explicitly labeled. Opening either project or news preview navigates with TanStack `resetScroll: false`, preserving the scrolled directory beneath Base UI's body scroll lock. Base UI owns outside-press dismissal; do not add a second backdrop click handler, because that consumes two history entries. Backdrop click, Escape, Close, and browser Back dismiss the preview and restore the prior directory URL/filter and scroll position; browser Forward reopens the masked preview, while refresh turns the public project URL into its standalone page. Focus returns to the triggering card or row.

## Boundaries and checks

Only recorded URLs belong to their sources. Do not invent entries, repository URLs, screenshots, or claims. Do not add analytics, remote icon kits, or an unrelated visual theme. Keep the full JSON and generated README available for audit without making them the first-read UI.

Verify both view modes, filtering, empty search, modified-click fallback, preview dismissal and focus return, desktop and narrow reflow, and light/dark parity. Check the real rendered page rather than assuming that a build alone validates composition.
