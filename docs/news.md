# Jev news integration

The site keeps GitHub projects as its primary directory. The sidebar's **Jev news** entry reuses the main card area for a separate, source-attributed news view. It does not mix news into `data/github.json`, the generated README, or the GitHub ranking. The news view uses the existing semantic colors, Geist type, card radius, and spacing; it does not import AIHOT styling.

## Source contract and media boundary

The scheduled collector uses [AIHOT REST API v1](https://aihot.news/agent), specifically `/api/v1/items?mode=all&window=7d&by=timeline&q=Jev&limit=100`. This matches the public Jev search's rolling window more closely than `by=published`. The official [OpenAPI schema](https://aihot.news/openapi-v1.json) supplies title, optional original title and summary, source name, AIHOT reading URL, original URL, publication/discovery times, category, score, selected flag and recommendation reason. It defines `timeline` as discovery time unless the source was back-filled more than 72 hours after publication, in which case it uses publication time. The UI applies that same rule to ordering, day groups and displayed times, with descending AIHOT ID as a tie-breaker. The API does **not** supply article body, image URLs, video URLs, thumbnails, or an item-detail media API.

News cards therefore display only API-contracted text and metadata. The summary, optional original title, and optional selection reason are shown in full on the card; the label is simply “Summary,” not “AIHOT summary.” A plain click opens our own summary preview and gives that item a stable `/news/{id}` public URL; browser Back returns to the previous news or Saved view. Modified clicks, copied links, and refresh reach a prerendered HTML page using the same content and clearly labeled AIHOT/original-source links. These pages do not pretend to contain the full article. AIHOT's reading page may show an image preview or direct the reader to the original post for video playback. We do not scrape AIHOT HTML or hotlink/copy third-party media. The aggregate News route uses a TanStack loader to prerender its first 16 source-attributed cards and hydrate the complete local archive. Its remaining timeline uses TanStack Virtual with measured, variable-height rows and preserved date headings; search works across the entire archive without a "show more" gate. The home route does not load the news archive; Saved still loads news only when a saved-news view is opened.

Build-time prerendering creates English, Chinese, and Japanese URL variants for news items with non-empty summaries. The per-item HTML includes the source-attributed summary, canonical URL, reciprocal language alternates, and metadata derived from stored facts; the shared content component keeps it identical to the preview. A one-line summary shorter than 60 characters still gets a working direct HTML link, but its page is `noindex` and excluded from `sitemap.xml`; only substantial stored summaries become search-entry candidates. The sitemap includes stable item URLs, not transient preview state. The aggregate `/news`, `/zh/news`, and `/ja/news` pages have real prerendered card content and appear in the sitemap. Browser-local `/saved` remains `noindex`.

The local Saved view may bookmark a news ID, but does not cache or republish its title, summary, or source material separately. It lazily loads the same `data/news.json` chunk when saved news is opened and shows only current catalog data. The save control is separate from the AIHOT reading link and the on-site summary preview.

## Incremental update and history limit

`mode=all` only exposes a rolling seven-day window; there is no official public endpoint for every historical item. The selected snapshot has older **selected** items, not the entire historical public pool. The first API run can therefore seed only the current window. Later hourly runs start a fresh query and follow the API's opaque `nextCursor` only **within that run**. A rolling-window cursor is not persisted across days. The AIHOT website search can show older results, but its HTML is neither this collector's stable contract nor a workaround for the source's body/media authorization boundary.

The collector validates the whole response before writing, merges by stable AIHOT ID, updates changed known rows, and appends new rows without reordering the existing JSON. Reports with distinct AIHOT IDs stay distinct even if they link to the same original URL; otherwise the local archive silently omits entries that AIHOT's own query includes. An API error, repeated cursor, or pagination safety-limit hit fails the run and leaves the previous file intact. The site sorts rows by AIHOT's timeline rule, while storage remains append-oriented for small Git diffs. Rows older than the first successful sync cannot be reconstructed from `mode=all`; the page must not claim to be an exhaustive historical archive. Conversely, older collected rows remain after they leave the API's rolling seven-day window, so our cumulative count need not equal the current AIHOT search count. The API has no exact withdrawal/change feed for `mode=all`, so removal or correction of older rows requires manual review.

The GitHub Action is scheduled for minute 43 every hour (UTC) and commits `data/news.json` together with the regenerated `public/sitemap.xml` when explicitly enabled. GitHub's scheduler may delay or drop a scheduled run; the cron expression is not a punctuality guarantee. Within a run, paginated requests are serial and at least 60 seconds apart, matching AIHOT's published `items` cache interval; a 429 retry waits at least `Retry-After` (or defers to the next scheduled run when it exceeds ten minutes). One transient 5xx retry is spaced by 60 seconds. The 15-page safety ceiling fails without publishing partial data. No AIHOT key, Jev key, MCP server, or browser scraper is required. Its write job is gated by repository variable `AIHOT_NEWS_ENABLED=true`; without it, scheduled and manual workflows do not publish AIHOT content. A normal build validates `data/news.json` and includes it in the site data-update time when it changes.

## Usage scope

[AIHOT's terms](https://aihot.news/terms) permit qualifying unsponsored, non-commercial open-source/public-interest use without applying, while treating public mirrors and bulk public redistribution separately. This implementation remains a Jev-specific, source-attributed section of an independent directory: it shows API summaries and outbound reading links, not full articles or media, and offers no news API or bulk export. The maintainer has chosen to operate it under the public-interest scope. Reassess before expanding it into a general AIHOT mirror, charging, adding sponsorship, or syndicating its data. The repository variable is a technical on/off switch, not a statement of endorsement or a substitute for any permission that a materially different use might require.
