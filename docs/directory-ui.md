# Awesome JEV directory UI

This document owns the directory's product-specific composition and behavior. Apply the stable visual tokens and review rules in [design.md](design.md); do not duplicate them here. The implementation lives in `src/App.tsx` and `src/components/*`.

## Reader and data

The current page helps readers find curated TypeSafe Jev / System One GitHub projects, judge their recorded summary and metadata, and inspect the original repository. It reads [`data/github.json`](../data/github.json). A distinct Jev news view reads [`data/news.json`](../data/news.json); X and YouTube records remain stored but hidden. Keep UI chrome localized in `src/i18n/locales/*` and retain source titles and summaries in their original language.

The opening viewport should reveal identity, searchable inventory, active controls, and the start of results. Keep the result set dominant rather than placing a marketing masthead ahead of the reader's task.

## Page composition

- The full-width sticky header contains the site title and three equal-size icon controls: source-repository link, theme menu, and language menu. The title returns to all projects and the top of the page. It uses the attributed React Bits `DecryptedText` source and its `motion/react` dependency with `speed=100`, `maxIterations=10`, `sequential=true`, `useOriginalCharsOnly=false`, `revealDirection=start`, `animateOn=hover`, and `clickMode=once`. The component's own character pool and reveal state remain upstream-owned. `maxIterations=10` has no effect in sequential mode; `clickMode` is inert outside click mode. Only pointer entry starts the decrypt; pointer exit restores the complete title, and a later entry replays it. There is no automatic loop. Reduced-motion readers see a static title. An invisible label reserves the final width without layout shift; the animated text stays on one line and may overhang during scrambling rather than wrap and clip the final letters. Both menus mark the current choice. Theme offers System, Light, and Dark; System follows operating-system changes, and selecting it clears any saved override. An effective color change uses a brief native crossfade where supported, but skips motion when the reader requests reduced motion. The language menu lists English and 简体中文, and both explicit theme and language choices persist across reloads. The header has no routine bottom divider.
- The centered content frame contains a full-width ASCII wordmark, two-line tagline, and data-update time when build history supplies one. Never manufacture a timestamp. The wordmark fits by CSS container width from first paint rather than resizing after hydration.
- On wide desktops (1280px and up), navigation occupies a 256px left rail beside the main results. The shared page frame is 1200px at most: the extra rail width enlarges the frame rather than taking width from the result cards. Labels stay on one line with counts in their own right-aligned space. The sticky rail scrolls independently on short viewports. Below that breakpoint the same navigation opens the existing shadcn/Base UI left Sheet, leaving the full content width to the cards. The Sheet is a restrained 288px navigation panel, not a page-width overlay: a visible localized title and aligned close action form its header above the independently scrolling list. The wordmark, results, and footer share the wider frame's edges. Top 100 Starred, Jev news, and Saved stay as three fixed shortcuts above the divider. All projects begins the project category group below it; only the categories below that point follow a stable English-label alphabetical order, with Other last, shared by both language settings. Top 100 Starred shows the highest-starred projects in the whole catalog; its limit is already in the label, so no duplicate count appears on the right. The cutoff uses global star rank, not the current search or sort order. Saved sits directly below Jev news; its browser-local count alone uses a compact outlined badge, while other counts remain aligned text from their respective data stores.
- Main controls are an underline search field, Stars / Date / Name sort, and cards / list view. Search is GitHub-only; query and the selected shortcut or category filter the results, sort orders them, and view changes their presentation. The Stars button has no ambiguous inventory count. Preserve the query when no items match.
- The cards view places each consecutive group of cards left-to-right on one reading row, even when card heights differ. It keeps cards at natural height rather than stretching them; preserving strict rank/date order takes priority over filling every short-card gap. Narrow screens use a single column. Once desktop card heights and positions are measured, offscreen card content can be skipped without losing its measured space; the full directory remains in the DOM. Card boundaries use an inset ring: the desktop `content-visibility` optimization clips an outside ring to the card box, leaving only corner fragments. The list view is a ranked table-like list of rank, project, and stars, not an activity dashboard.
- The footer ends the directory with a brief source note. Keep the opening and closing of the page connected even when the filtered result set is short.

The news shortcut swaps the main result area, not the header or design system. It has local text search, source attribution, newest-first order, and an incremental “show more” control rather than rendering an unbounded archive at once. Unlike the compact GitHub grid, news uses full-width cards grouped by Shanghai calendar date with a time rail, source line, AIHOT score when present, title, complete API summary, complete optional original title, and complete optional selection reason. Do not truncate these scarce reading fields merely to equalize card heights. The layout borrows the reading order of AIHOT's timeline but retains our tokens and radii. A plain click opens our own accessible, dismissible summary dialog with the original-source and AIHOT reading links; modified clicks retain the AIHOT link fallback. There is no redundant “View details” label on the card: the dialog supplies outbound actions, not a promised full article. The dialog does not claim to display the article body or media, because the official API does not expose those fields; see [news.md](news.md) for the source boundary.

Saved is a browser-local reading list, not a repository data source or an account. The one `SaveButton` component appears on project cards, list rows, news cards, and both previews. It uses Phosphor's single-chevron `BookmarkSimple` rather than a star, so GitHub stars retain their original meaning. The visible project title is the source link with a stretched click area over the card; `SaveButton` sits separately in `CardAction`, never inside that link, so activating it must neither navigate nor open the preview. On project cards the button sits in `CardAction`, centered to the title row without contributing to its row height; `CardDescription` spans both grid columns and keeps the full card width. The rank badge replaces the redundant GitHub mark at the start of the title row. No title or header padding is added to simulate the button column. On news cards it aligns with the source row's right content edge without crowding source or score. List rows align it to the row's right content edge. Cards and rows use a visually compact 32px control with an invisible 40px pointer target; previews keep a 40px control beside Close. Visible focus, `aria-pressed`, and distinct add/remove labels make the state usable without relying on color alone.

The Saved view separates projects from news, then offers only populated categories from each source's existing taxonomy; it does not invent user folders or merge incompatible category systems. Its search acts on the selected source, and cards reuse the regular project/news components and preview behavior. Browser storage contains only source-namespaced IDs and save times, never copies of titles or summaries; current catalog data owns display. Missing catalog IDs appear as removable unavailable entries rather than showing stale copied content. Storage denial leaves the displayed state unchanged and shows an error; updates in another tab refresh this view. Clearing browser data or switching devices loses these bookmarks. No key, analytics, server sync, or Action write is involved.

## Card ordering algorithm

`CardMasonry` receives items **after** search, filter, and sort. It must not change that sequence. On a desktop-sized grid, the column count comes from the CSS breakpoint (two or three), not from card content. The layout measures each card's natural height and converts it to a four-pixel grid-row span including a 16-pixel gap. Cards are assigned round-robin to columns 1, 2, 3, then each new card starts immediately after the previous card **in its own column**. This preserves the first row's left-to-right sequence and keeps each column in source order without leaving row-wide holes.

True masonry cannot also guarantee strict row-by-row visual rank order when card heights differ: a later card in a shorter column can start above an earlier card in a taller column. Source and keyboard order remain unchanged; rank labels make the intended ordering explicit. On narrow screens, cards use one-column document flow. The desktop layout records each measured height as an intrinsic-size fallback before enabling offscreen `content-visibility`, so skipped cards keep their space during scrolling and theme changes.

## Project evidence

GitHub cards show title, summary, source repository / language, recorded stars / forks, and tags when available. Separate title, summary, source, metrics, and tags with a consistent 12px vertical rhythm; changing row spacing must not squeeze the title/action columns or the summary width. Keep stars and forks in one non-wrapping flex row; their variable-width numbers do not need fixed grid columns. Open-issue counts are neither persisted nor shown: without context, the number is not a useful quality signal. Global star rank uses the existing subdued outlined number badge before the title, replacing the redundant GitHub mark; it is not a second star count or the current filtered-list position. The top-right corner stays reserved for Save, and long titles wrap beside the badge rather than moving it to a separate line. Counts and sort keys come from `sourceMeta`; never substitute invented values. Peer cards keep the same type roles and metadata order even when summaries have unequal lengths.

An ordinary click on a card or list row opens the single shared project preview. The stretched title anchor still points to the original GitHub URL for no-script fallback and modified clicks. The preview shows only stored facts: title, repo identifier, summary, category, language, available star/fork counts, optional pinned review-source link, and tags. It does not fetch or render a third-party README. Make the summary the main reading block; counts are compact evidence, not a three-column dashboard. Do not repeat the rank badge.

The preview has a dim backdrop and one restrained surface. A narrow dialog scrolls its content without covering it with the header or outbound action. The GitHub action is explicitly labeled. Backdrop click, Escape, and the close control dismiss the preview and return focus to its triggering card or row.

## Boundaries and checks

Only recorded URLs and remote media belong to their sources. Do not invent entries, tweet IDs, screenshots, or claims. Do not add analytics, remote icon kits, or an unrelated visual theme. Keep the full JSON and generated README available for audit without making them the first-read UI.

Verify both view modes, filtering, empty search, modified-click fallback, preview dismissal and focus return, desktop and narrow reflow, and light/dark parity. Check the real rendered page rather than assuming that a build alone validates composition.
